# 🎰 Казино на Фантики — Telegram-бот

**Стек:** Python 3.11 · aiogram 3.x · PostgreSQL · APScheduler · Railway.app

Полный функционал по ТЗ: 7 игр, реферальная цепочка, кэшбек, промокоды,
магазин бустов за **Telegram Stars**, админ-панель с **настройкой мини-игр
через кнопки и контекст**, Reply-клавиатура внизу чата.

---

```
bot/
├── bot.py              # entrypoint
├── config.py           # env + константы ТЗ
```

## 🚨 ОБЯЗАТЕЛЬНО ПЕРЕД ПОВТОРНЫМ ДЕПЛОЕМ MINER v7

Если старая версия «как будто не меняется», Railway почти наверняка запускает
не тот root/commit или второй старый polling-инстанс.

1. Если GitHub содержит весь проект, в сервисе Railway укажи:
   **Settings → Source → Root Directory = `/bot`**.
   Если файлы `bot.py`, `requirements.txt`, `railway.json` уже в корне репо —
   Root Directory должен быть пустым.
2. Settings → Deploy → Start Command: `python -u bot.py`.
3. Settings → Deploy/Regions → **Replicas = 1**. Два экземпляра polling запрещены.
4. Variables добавь `BOT_VERSION=miner-v7-postgres-fsm-2026-08-27`.
5. Deployments → меню последнего деплоя → **Redeploy / Clear build cache**.
6. Останови старый Railway-сервис и локальный `python bot.py`, если он запущен.
7. В логах нового деплоя должны быть строки:
   ```
   START version=miner-v7-postgres-fsm-2026-08-27 commit=...
   Database schema verified: {'ok': True, ..., 'fsm': True}
   READY @your_bot ... version=miner-v7-postgres-fsm-2026-08-27
   ```
8. В Telegram отправь:
   - `/version` → обязан показать `miner-v7-postgres-fsm-2026-08-27`
   - `/health` → обязан показать `✅ OK`, `PostgreSQL FSM: OK`
   - `/start` → очищает старое состояние диалога
   - `/miner_debug` → покажет текущее FSM и активную партию

Если `/version` показывает другое — **новый код вообще не запущен**. Исправлять
игровую логику бессмысленно, пока Railway не стартует правильный root/commit.

## 🚀 ДЕПЛОЙ НА RAILWAY — ПОШАГОВО

### 0. Подготовка бота в Telegram

1. Открой [@BotFather](https://t.me/BotFather) → `/newbot`
2. Придумай имя и username (например `FantikiCasinoBot`)
3. Скопируй **токен** вида `123456:AA...`
4. (Рекомендуется) `/setjoingroups` → Enable — чтобы бот работал в группах
5. (Рекомендуется) `/setprivacy` → Disable — чтобы бот видел команды в группах
6. Для **Telegram Stars** ничего дополнительно настраивать не нужно:
   `currency="XTR"` + пустой `provider_token` — работает из коробки.

### 1. Аккаунт Railway

1. Зайди на [railway.app](https://railway.app) → Sign up (через GitHub удобнее)
2. Confirm email

### 2. Создай проект

**Вариант A — из GitHub (рекомендуется)**

1. Залей папку `bot/` в репозиторий GitHub.
   Важно: **корень репозитория = содержимое `bot/`**
   (то есть `bot.py`, `Procfile`, `requirements.txt` лежат в корне репо).

   Если весь монорепо — укажи Root Directory = `bot` в настройках сервиса.

2. Railway → **New Project** → **Deploy from GitHub repo** → выбери репо
3. Railway подхватит `Procfile` / `requirements.txt` автоматически

**Вариант B — через CLI**

```bash
# Установи Railway CLI
npm i -g @railway/cli
# или: brew install railway

railway login
cd bot
railway init          # создаст проект
railway up            # задеплоит текущую папку
```

**Вариант C — Drag & Drop**

1. New Project → Empty Project
2. Add Service → Empty Service
3. Settings → Source → подключи GitHub / или используй `railway up` из CLI

### 3. Добавь PostgreSQL

1. В проекте Railway нажми **+ New** → **Database** → **Add PostgreSQL**
2. Railway создаст БД и переменную `DATABASE_URL` автоматически
3. Привяжи переменную к сервису бота:
   - открой сервис бота → **Variables** → **Add Variable** →
     **Reference** → выбери `DATABASE_URL` из Postgres-плагина
   - **ИЛИ** в настройках сервиса: Settings → Service Variables →
     Connect / Share variable from Postgres

> ⚠️ Бот сам нормализует URL: `postgresql://…` → `postgresql+asyncpg://…`
> (asyncpg требует такой префикс). Ничего руками менять не надо.

### 4. Переменные окружения бота

Открой сервис бота → **Variables** → добавь:

| Variable           | Value                                      | Обязательно |
|--------------------|--------------------------------------------|-------------|
| `BOT_TOKEN`        | токен от @BotFather                        | ✅          |
| `DATABASE_URL`     | (reference из Postgres)                    | ✅          |
| `ADMIN_USERNAMES`  | `f0nt1ew,slash_zzzz`                       | рекомендуется |

### 5. Start Command / Procfile

Railway читает `Procfile`:

```
worker: python -u bot.py
```

Если Procfile не подхватился — в Settings → Deploy → **Custom Start Command**:

```
python -u bot.py
```

`-u` = unbuffered stdout (логи видны сразу).

### 6. Deploy

1. Нажми **Deploy** (или push в GitHub — auto-deploy)
2. Открой **Deployments** → **View Logs**
3. Жди строки:
   ```
   Инициализация БД…
   БД готова.
   Бот запущен: @YourBotName (id=…)
   Scheduler started. Next run: …
   ```
4. Если видишь `BOT_TOKEN не задан` — проверь Variables и Redeploy
5. Если ошибка подключения к БД — проверь, что `DATABASE_URL` привязан
   именно к сервису бота (не только к Postgres-плагину)

### 7. Проверка

1. Открой бота в Telegram → `/start`
2. Внизу чата должна появиться **Reply-клавиатура** с кнопками:
   ```
   🎲 Игры     🏆 Топ
   🎁 Бонус    🔄 Кэшбек
   👥 Рефералы 🛍 Магазин
   🎫 Промокод 📊 Статистика
   💰 Баланс
   ```
3. Админам (`@f0nt1ew`, `@slash_zzzz`) дополнительно видна кнопка `🔐 Админ`
   (или команда `/secretadmin`)

### 8. (Опционально) Кастомный домен / healthcheck

Бот работает через **long polling** — HTTP-порт не нужен.
Railway может ругаться «no open ports» — это нормально для worker-сервиса.
В Settings → Networking можно ничего не открывать.

Если Railway требует HTTP — добавь простой health-сервер, но для polling
это не обязательно. Тип сервиса — **Worker**.

## 🎮 Как пользоваться

### Игрок

Все действия — **кнопками внизу чата** (Reply Keyboard).  
Майнер дополнительно рисует **Inline-поле** (сетка клеток) прямо в сообщении.

| Кнопка / команда | Что делает |
|---|---|
| `/start` | Регистрация + главное меню |
| `/start ref_XXXX` | Регистрация по реф-ссылке |
| 🎲 Игры | Список мини-игр |
| ⛏ Майнер | «Сапёр наоборот»: игрок сам задаёт поле 3×3…30×30, мины 1..N²−2 и ставку (дробную, до 1e21) |
| ⬆ Лесенка | Ставка → ступень 1..12 → до ×101 |
| ♠ Блэкджек | Ставка → ➕ Ещё / ✋ Стоп |
| 🔺 Больше/Меньше | Ставка → Больше/Меньше 50 · ×1.9 |
| 🎲 Кости | Ставка → число 1..6 · ×5.5 |
| 🎰 Слоты | Ставка → 3 барабана |
| 🔴 Рулетка | Ставка → Красное/Чёрное/Чёт/… |
| 🏆 Топ | 5 вкладок лидерборда |
| 🎁 Бонус | +1 000 🍬 каждые 5 мин (×2 с бустом) |
| 🔄 Кэшбек | 10% с проигрышей за день |
| 👥 Рефералы | Ссылка + статистика цепочки |
| 🛍 Магазин | Бусты за ⭐ Stars (инвойс Telegram) |
| 🎫 Промокод | Ввод кода |
| 📊 Статистика | Баланс + 10 последних транзакций |
| `/top` `/balance` | Работают и в **группах** |

### Админ (`@f0nt1ew`, `@slash_zzzz`)

1. Кнопка **🔐 Админ** (или `/secretadmin`)
2. Доступно:
   - 🎫 Создать промокод (FSM: сумма → активации → описание)
   - 💰 Выдать Фантики / ⭐ Выдать Stars
   - ⚙️ **Настройки игр** ← главное
   - 📊 Админ-статистика
   - `/give username amount`

#### ⚙️ Настройки мини-игр (через кнопки + контекст)

```
⚙️ Настройки игр
  → выбираешь игру кнопкой (✅/❌ + название)
  → Майнер (размер/мины/ставку игрок ВВОДИТ сам в игре):
       growth 1.05   ← множитель за каждый алмаз
       cap 100       ← потолок коэффициента
  → Больше/Меньше, Кости, Рулетка, Блэкджек:
       пришли число → новый коэффициент (например 1.9)
  → Слоты: JSON выплат {"🍒":3,"💎":100,"7️⃣":500}
  → Лесенка: JSON ступеней [{"coef":1.1,"chance":92},…]
  → любая игра: ✅ Включить / ❌ Выключить, ✏️ Ставки (кроме Майнера — там ввод свободный)
```

#### ⛏ Механика Майнера («Сапёр наоборот»)

Настройка партии — пошагово. На каждом шаге **пресет-кнопки + кнопка
`✏️ Ввести вручную`**, после которой ты печатаешь значение сам:

```
Шаг 1/3 · размер поля (3–30)
  [3×3] [5×5] [8×8]
  [10×10] [15×15] [30×30]
  [✏️ Ввести вручную]      ← жмёшь и пишешь, например 7
  [🎲 Игры] [🏠 Меню]

Шаг 2/3 · мины (1…N²−2)
  [💣 1] [💣 3] [💣 12] [💣 24]
  [✏️ Ввести вручную]      ← пишешь, например 17

Шаг 3/3 · ставка
  [10] [100] [1000]
  [0.5] [1e6] [1e9]
  [✏️ Ввести вручную]      ← пишешь 0.0001 / 250 / 1e21 — что угодно
```

Точно так же устроена ставка в **каждой** игре (Лесенка, Блэкджек,
Больше/Меньше, Кости, Слоты, Рулетка): пресеты + `✏️ Ввести вручную`.

* 💎 Алмаз → коэффициент растёт; 💥 Мина → ставка сгорает. Первый ход никогда не мина.
* 🚫 **Сброс партии** — если не открыто ни одной клетки, ставка возвращается
  полностью. Есть открытые → сброс запрещён, используй «💰 Забрать».
* Поля ≤ 8×8 — inline-кнопки; больше — текстовая сетка + координаты `строка колонка`.
* 💎 Алмаз → коэффициент растёт; 💥 Мина → ставка сгорает. Первый ход никогда не мина.
* Рост коэффициента **детерминированный** — каждый алмаз умножает на фикс. `growth`:
  ```
  mult(n) = growth^n          (по умолчанию growth = 1.03, потолок cap = ×100)
  1 алмаз → ×1.03 · 2 → ×1.0609 · 3 → ×1.0927 · 10 → ×1.3439
  50 → ×4.38 · 100 → ×19.2 · дальше — упирается в cap
  ```
  В интерфейсе всегда показан текущий коэф. и коэф. следующего алмаза.
* Поля ≤ 8×8 — inline-кнопки; поля больше — текстовая сетка,
  клетки открываются координатами: `строка колонка` (например `3 7`).
* Балансы и ставки хранятся как `NUMERIC(40,10)` — дробные значения и гиганты
  до 1e21 без потери точности (старые integer-колонки мигрируются автоматически).

#### 🎚 Настраиваемые коэффициенты ВСЕХ игр (админка)

| Игра | Что настраивается | Как |
|---|---|---|
| ⛏ Майнер | `growth` (множитель за алмаз), `cap` (потолок) | `growth 1.05`, `cap 100` |
| 🔺 Больше/Меньше | коэффициент выплаты | число `1.9` |
| 🎲 Кости | коэффициент выплаты | число `5.5` |
| 🔴 Рулетка | коэф. равных шансов | число `2.0` |
| ♠ Блэкджек | выплата при победе | число `2.0` |
| 🎰 Слоты | таблица выплат 3-в-ряд | JSON `{"🍒":3,"💎":100}` |
| ⬆ Лесенка | все ступени (коэф + шанс) | JSON `[{"coef":1.1,"chance":92},…]` |

Всё сохраняется в БД (`bot_settings`) и применяется мгновенно, без рестарта.

Все настройки пишутся в таблицу `bot_settings` и применяются **сразу**,
без рестарта бота.

## ⭐ Telegram Stars

Магазин шлёт инвойс:

```python
await bot.send_invoice(
    chat_id=...,
    title="🛍 x2 Кэшбек",
    description="...",
    payload="buff_x2_cashback",
    provider_token="",      # для Stars — пустая строка
    currency="XTR",         # код валюты Telegram Stars
    prices=[LabeledPrice(label="...", amount=15)],  # amount = кол-во Stars
)
```

Обработчики: `pre_checkout_query` (ok=True) + `successful_payment` → активация буста.

| Буст | Stars | Эффект |
|---|---|---|
| x2 Кэшбек | 15 | кэшбек 20% · 24ч |
| x1.5 Коэффициенты | 35 | выигрыши ×1.5 · 24ч |
| x3 Кэшбек | 40 | кэшбек 30% · 24ч |
| Страховка | 50 | возврат 50% ставки · 1 заряд |
| x2 Бонус | 20 | бонус 2 000 🍬 / 5 мин · 12ч |

Админ может «начислить» Stars через панель (для тестов) — это внутренний счётчик.
Реальные покупки идут через Telegram Payments.

## 🔧 Частые проблемы

| Симптом | Решение |
|---|---|
| `BOT_TOKEN не задан` | Variables → `BOT_TOKEN` → Redeploy |
| `connection refused` к БД | Привяжи `DATABASE_URL` reference к сервису бота |
| `password authentication failed` | Используй reference-переменную, не копируй руками |
| `column users.tg_id does not exist` | БД создана старой версией. `init_db()` сам добавит колонку при старте — просто сделай Redeploy |
| Бот не отвечает | Смотри логи: Deployments → View Logs |
| Кнопки не видны | `/start` заново — Reply-клавиатура придёт с меню |
| Кнопка «✏️ Ввести вручную» молчит | Значит ты не на шаге настройки — сначала выбери игру (бот напишет об этом) |
| Stars-инвойс ошибка | Убедись, что `currency="XTR"` и `provider_token=""` |
| Railway «no open ports» | Нормально для worker/polling. Игнорируй или поставь тип Worker |
| Админка не открывается | Юзернейм должен точно совпадать (`f0nt1ew` / `slash_zzzz`), без `@` |

### Авто-миграции БД

При старте `init_db()` сам доводит уже существующую БД до актуальной схемы:
добавляет `users.tg_id`, переводит денежные колонки в `NUMERIC(40,10)`
(дробные ставки и числа до 1e21). Дополнительно ничего запускать не нужно —
достаточно Redeploy.
